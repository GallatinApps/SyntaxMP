# SyntaxMP Fixture Coverage Inventory

This inventory records construct-level fixture coverage for SyntaxMP's built-in tokenizers. It is the durable map for what the library fixtures intentionally protect, what source support exists but still needs focused assertions, and what remains deferred.

Fixture coverage is the authority for tokenizer correctness and emitted-role coverage.

Update this file whenever tokenizer behavior or fixture coverage changes. Demo samples remain showcase and discovery material; correctness anchors belong in `syntaxmp/src/commonTest/.../languages/fixtures/`.

Last audited: 2026-05-30. Each row was checked against its fixture file plus the owning tokenizer/scanner source (and shared scanner source where applicable).

## Status Key

| Status | Meaning |
|---|---|
| `Covered` | Important constructs for the current tokenizer contract are fixture-backed. |
| `Partial` | Useful fixtures exist, but named construct or negative-test gaps remain. |
| `Deferred` | Construct coverage is intentionally postponed, with a reason and follow-up route. |
| `Not applicable` | The construct family does not apply to the language row. |

`Not applicable` is used inside cells for construct families that do not need follow-up. Rows marked `Partial` name a concrete follow-up route. Deferred constructs are dated in the gap or follow-up cell.
